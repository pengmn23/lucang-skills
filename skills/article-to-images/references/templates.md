# 模板：保存与使用

模板是一套**去掉了具体内容、只留风格和版式**的提示词。存一次，下次做别的内容时说「用模板 U001」，就能沿用同样的画法、配色、字体和版式。

模板存在本 skill 的 [`my-templates/`](../my-templates/README.md) 文件夹里，索引是 `my-templates/README.md`。

## 1. 什么时候问用户要不要存

| 时机 | 怎么问 |
|---|---|
| 做完一套图或一张图（提示词已交付；如果出了图，首图或单张已检查） | 「要不要把这套的风格和版式存成模板？下次做别的内容可以直接说『用模板 U00X』。」 |
| 拆完一张图（见 [拆解图片](deconstruct.md) 第 7 节） | 在「转成九区提示词／存成模板」的询问里一起问 |

每次只问一句。用户没回应或说不要，就不再追问。用户主动说「把这个存成模板」时直接执行。

## 2. 存什么

```text
my-templates/
├── README.md                  模板索引
└── U001_模板名/
    ├── 模板说明.md             这套模板是什么、适合什么、怎么用（必有）
    ├── 模板.json               去主体的九区提示词（必有）
    ├── 示例.json               一份完整的原始提示词，作对照（可选）
    ├── 版式清单.md             系列模板：每张用的版式与节点结构（系列才有）
    ├── 七维拆解.json           拆图来的模板：原图的七维拆解（拆图才有）
    └── 参考图.png              用户同意才存（可选）
```

- **编号**：`U` 加三位数字，从 `U001` 起，取索引里最大的编号加 1。
- **模板名**：6—12 字，说清风格和用途，例如「铜版档案分组表」「白底手绘干货卡」。和用户确认一次名字。

### 模板说明.md

```markdown
# U001 铜版档案分组表

- 来源：2026-11-05 做的系列《XX》，共 10 张（或：拆解自用户提供的一张图）
- 类型：小红书图文系列｜知识图解（分组表格）
- 比例：3:4　密度：高，约 300 字
- 风格要点：细密铜版蚀刻排线、米灰旧档案纸、墨黑＋朱红＋暗金
- 版式要点：顶部标题＋徽章排＋11 行完整表格＋底部金句
- 适合：分组多、条目多、需要查阅的内容
- 不适合：情绪类、少字海报
- 参考图：有（参考图.png）／无，原图位置：……
- 注意：表格超过 5 列时字会很小；强调词不要放「序列0」这类会被加到每行的词
```

「注意」写这次做图或拆图中发现的问题，下次用时先避开。

### 模板.json（去主体规则）

从本套的风格母版（单张就用那一份 JSON；拆图来的先按 [拆解图片](deconstruct.md) 第 8 节转成九区格式）出发：

| 字段 | 处理 |
|---|---|
| 视觉风格系统、标题艺术系统（除标题文字）、内容标签系统、配色方案、光影效果、渲染参数与负向 | **逐字保留**；其中提到的具体主体（如「叶绿用于薄荷」）换成方括号「叶绿用于[主体]」 |
| 画布比例、语言规范、阅读场景、视觉美学 | 保留 |
| 角色设定 | 角色是风格的一部分（如固定吉祥物）就保留；是本次故事的人物就换成【填写】 |
| 核心主题、标题文字内容、系列编号、页码标注 | 换成 `【填写】` |
| 布局架构、视觉逻辑 | 保留结构和比例，把具体主体换成方括号，如「中部 3×3 九张[条目]档案卡」 |
| 核心内容要素 | 保留节点数量、节点角色、节点布局结构、位置/引线；视觉锚点里的具体主体换成方括号；标题、描述、强调词清空成 `【填写】`／`[]` |
| 硬性指令约束 | 保留通用条目；删掉只和原内容有关的条目（专名、具体数字） |

去主体后通读一遍：模板里**不能留下原内容的专名、原文、人名、品牌和数据**。

系列模板另写 `版式清单.md`：每张一行，写版式名称、布局架构、根节点角色序列，例如「表格页：副标题→列首徽章组→表格→金句」。

### 要不要存参考图

保存时问一句：

> 要不要把[首图／原图]也存进模板？存了以后，下次用这个模板出图可以直接附上它作风格参考；但分享这个 skill 前，记得删掉 `my-templates` 里的图片。

- 同意：复制一张图到模板文件夹，命名 `参考图.png`（保持原格式后缀）。只存一张：系列存首图，拆图存原图。
- 不同意：只在模板说明里记下图片原来的位置。

### 更新索引

在 `my-templates/README.md` 的表格里加一行：编号、名称、来源、类型、比例、密度、有无参考图、日期。

### 没有文件写入权限时

把要写的每个文件内容按顺序完整给出，告诉用户在 `my-templates/` 下新建对应文件夹和文件，并在索引里加一行。说明「尚未保存」，不要说已经存好。

## 3. 使用模板（只在用户点名时）

只有用户说「用模板 U001」「用我存的铜版档案模板」「我有哪些模板」时，才读 `my-templates/`。没有点名就照常走做图流程，不主动推荐已存模板。

1. 用户问「有哪些模板」：读索引，列出编号、名称、类型和一句话要点。
2. 用户点名一个模板：读它的 `模板说明.md` 和 `模板.json`；系列模板再读 `版式清单.md`。
3. **风格视为已选**，不再问风格三选一。仍按 [前置提问](preflight.md) 问密度（模板说明里的密度作为推荐项）；系列再问两道内容题。
4. 风格字段从 `模板.json` 逐字复制；版式优先沿用模板，内容放不下时可换 [04 版式库](../library/04_版式布局.md) 里的版式，并告诉用户。
5. 先读「注意」一栏，避开上次出过的问题。
6. 出图时如果模板里有 `参考图`，并且工具支持参考图，就附上它作风格参考（附图说明见 [系列与交付](series-and-delivery.md#首图参考出图)）。系列仍然先出第 1 张，确认后以**新的首图**为锚。

## 4. 管理

- **改名、改说明、补注意事项**：用户要求就改，同步索引。
- **更新模板**：用户说「用这次的结果更新 U001」时，先列出会变的字段，确认后覆盖，并在模板说明里记一行更新日期。
- **删除模板**：只在用户明确要求时删，删前确认一次编号和名称；删后同步索引。

## 5. 分享前注意

`my-templates/` 存的是用户自己的东西：

- 参考图和 `七维拆解.json` 可能含他人作品的画面或原文转录，只供自己参考，不要随 skill 公开分享。
- 分享 skill 前，建议清空 `my-templates/`（保留 `README.md`），或只留自己原创、已去主体的模板。
